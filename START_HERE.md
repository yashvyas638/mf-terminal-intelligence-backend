# Start here — non-developer deployment guide

## What you have
This ZIP is the first backend phase for your **existing** MF Terminal Intelligence plugin. It is not a second plugin and it is not deployed yet.

## Step 1 — Put the code in a private GitHub repository

1. Download `mf-terminal-cloud-phase1.zip` from this chat and unzip it.
2. In your browser, sign in to GitHub and create a **new private repository** named `mf-terminal-intelligence-backend`. Do not add a README, licence, or `.gitignore` at creation time.
3. On your Mac, install GitHub Desktop from `https://desktop.github.com/` and sign in.
4. In GitHub Desktop choose **File → Add Local Repository** and select the unzipped `mf-terminal-cloud` folder. If it says the folder is not a repository, choose the option to create a repository there; keep the existing files.
5. Commit the files with a message such as `Add AMFI NAV ingestion foundation`.
6. In GitHub Desktop choose **Publish repository** and select the private repository you created. Confirm it stays **Private**.

If GitHub Desktop cannot add the existing folder cleanly, stop and share a screenshot rather than deleting or moving files.

## Step 2 — Create persistent PostgreSQL storage

Use a managed PostgreSQL service such as Supabase. Create a database project, open its connection details, and copy the **session/direct connection string** intended for server-side applications. Do not paste the database password or URL into this chat, and do not commit it to GitHub.

## Step 3 — Deploy the API

1. Create/sign in to a Render account and create a new **Web Service** from your private GitHub repository. Grant Render access to only this repository if offered.
2. Runtime: Python. Build command: `pip install -r requirements.txt`. Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
3. Add environment variable `DATABASE_URL` with the PostgreSQL connection string.
4. Add environment variable `API_KEY` with a long random secret generated by a password manager. Keep it private.
5. Deploy. The first deployment may fail if the database URL is copied incorrectly; fix the environment variable and redeploy rather than placing credentials in code.

Cloud services and database plans may cost money. Check current pricing before creating paid resources. Do not proceed with a paid plan unless you approve its cost.

## Step 4 — Run the live acceptance test

1. Open `https://YOUR-SERVICE.onrender.com/health`. Expected: JSON with `status: ok` and `database: reachable`.
2. Open `https://YOUR-SERVICE.onrender.com/docs`.
3. Expand `POST /v1/nav/refresh`, click **Try it out**, add request header `X-API-Key` with your secret, then execute.
4. Expected: a nonzero record count, a payload hash, NAV date range and a validation status. If the source fails, the endpoint should return an error and preserve the previously stored data.
5. Use `GET /v1/nav/status` and `GET /v1/nav/schemes` with the same header to confirm persistence.

Do not share screenshots that expose the API key, database URL, password, or other secrets.

## Step 5 — Schedule daily refresh

After the API works, configure GitHub Actions repository secrets:

- `MF_TERMINAL_API_URL`: deployed service base URL, without a trailing slash.
- `MF_TERMINAL_API_KEY`: the same API key set in Render.

The included workflow runs Monday–Saturday at 09:30 India time by default. Trigger it manually once and verify the run succeeds. This is an initial schedule, not proof that AMFI publishes a complete NAV file at that exact time every day; adjust based on observed source availability.
