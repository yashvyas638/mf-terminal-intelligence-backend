# AMFI historical NAV backfill — implementation contract

## Verified source facts

- AMFI's official NAV Download page exposes a NAV History form with mutual-fund, type, from-date and to-date selections.
- AMFI explicitly limits each historical NAV download to a maximum period of 90 days.
- Official page: https://www.amfiindia.com/net-asset-value/nav-download

The exact form submission contract (HTTP method, endpoint parameters, fund/type identifiers, response headers and payload variants) is **not yet verified**. A guessed query string is not an approved source adapter.

## Foundation delivered in this change

- Deterministic inclusive date-window planner; every request window is at most 90 calendar days.
- Contiguous ranges with no overlap or missing dates.
- Stable SHA-256 window keys for idempotent job/checkpoint identity.
- Resume helper that skips windows already marked complete.
- No network calls, database writes, schema changes, or production ingestion.

## Required next implementation gates

1. Capture and document a real request generated by AMFI's own NAV History form for one known AMC and a short date range.
2. Verify the response is text, has a recognised header/row contract, and matches the selected AMC/type/date filters.
3. Build parser fixtures from that official response, including empty/error/HTML and malformed responses.
4. Add a durable job/checkpoint schema with per-window status, attempt count, source hash, row counts and error class; never mark a window complete before its transaction commits.
5. Add idempotent persistence keyed by scheme code + NAV effective date, retaining correction provenance and preserving known ISINs when the source omits them.
6. Add bounded retries, backoff, per-source rate limiting, pause/resume and operator visibility.
7. Reconcile planned windows, fetched windows, parsed rows, inserted/updated/unchanged rows, duplicate keys and per-scheme coverage.
8. Run the complete migration and workload in staging; only then consider production backfill.

## Non-goals / safety

- Do not infer the AMFI type parameter from third-party examples.
- Do not treat a successful HTTP response as proof of correct date/AMC/type filtering.
- Do not overwrite current NAV rows with incomplete or unvalidated batches.
- Do not fabricate dates for weekends/holidays or interpolate missing NAVs.
- Do not run a production historical backfill until source-contract validation, staging reconciliation and an explicit operator go-ahead are complete.
