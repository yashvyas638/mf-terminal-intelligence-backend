# AMFI historical NAV parsing foundation

## What is verified

The official AMFI NAV Download page exposes a NAV History form and states that historical NAV can be downloaded for a maximum period of 90 days at a time:
https://www.amfiindia.com/net-asset-value/nav-download

## Delivered in this change

- A pure date-window planner that creates contiguous, inclusive windows of at most 90 days.
- Stable SHA-256 window keys for future idempotent checkpoints.
- A strict parser for the historical eight-column NAV row layout, separate from the six-column daily NAVAll.txt parser.
- Validation for empty/HTML responses, malformed headers, invalid NAVs/dates, duplicate scheme/date rows and conflicting NAV values.
- Unit tests only. No HTTP request, database write, migration, schedule or production backfill is enabled.

## Important source-contract limitation

The exact HTTP request generated by the official form (including the scheme-type selector parameter and response variants) has not yet been captured and verified against AMFI itself. The commonly observed portal endpoint is a candidate only. Do not enable a production adapter or backfill until a real request/response is captured from the official form and reconciled against its selected scheme type and date range.

## Next gates

1. Capture the official form's actual request for a short date range and one scheme type.
2. Save a redacted response fixture with source URL, retrieval timestamp, HTTP status and payload hash.
3. Verify that response records are restricted to the requested date range and scheme type.
4. Build bounded retry and streaming transport only after this contract is confirmed.
5. Add durable checkpoints and atomic persistence in a separate migration after PostgreSQL staging tests.
6. Run a staging backfill and reconcile counts before any production execution.

No historical NAV is fabricated, interpolated or backfilled by this parser-only change.
